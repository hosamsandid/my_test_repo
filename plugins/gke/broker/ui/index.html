GKE Cluster Access

Read-only kubectl for this team's agents, brokered so the cloud credential never enters an agent container. Sign the broker in to GCP once here (team-admin only).

What this plugin does

It gives this team's agents read-only kubectl access to the team's GKE cluster, reached through the GCP Connect Gateway. Once it is set up here, granted agents can inspect the cluster with the aee-gke CLI — for example:

  • aee-gke get ns
  • aee-gke get pods -n platform
  • aee-gke describe deploy <name> -n <ns>
  • aee-gke logs <pod> -n <ns>
  • aee-gke api-resources

Strictly read-only. Only read verbs are exposed (get / describe / logs / api-resources). There is deliberately no apply, create, edit or delete — an agent cannot change or remove anything in the cluster.

Why the sign-in — and why this is a plugin. The Google cloud credential is held by the broker and never enters an agent container. A team admin signs in once here; from then on the team's agents read the cluster without ever handling a credential.

What happens next. After a successful sign-in, the team's granted agents can use the capability straight away. If an agent later reports it is not signed in, this is the page where a team admin re-authenticates.
